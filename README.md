# Social Media Trend Detection and Sentiment Analytics (Big Data Mini Project)

**Extension of Experiment 1:** Social Media Analytics for Trend Detection and Virality Prediction.

This project uses PySpark for data preparation and aggregation, scikit-learn for an optional classification task, and Streamlit for an interactive dashboard. It is designed for local execution on Windows, macOS, or Linux.

## Dataset

Primary dataset: [Multi-Platform Social Sentiment Evolution on Kaggle](https://www.kaggle.com/datasets/sohumgokhale/multi-platform-social-sentiment-evolution).

The Experiment 1 PDF lists the desired fields, but it did not include a separate CSV attachment. Download `multi_platform_social_sentiment_evolution.csv` from Kaggle and place it in this project's `data/` folder. The application can also let you upload a CSV through the sidebar.

**Dataset access note:** Kaggle may require signing in. This project does not scrape Kaggle or bypass access restrictions.

## Features

- Data quality checks: row counts, duplicate IDs/rows, missing values, inferred columns.
- PySpark aggregations for platform comparisons, hashtag/topic rankings, sentiment distribution, and time-based trends.
- Interactive Streamlit dashboard with filters and charts.
- Optional machine-learning classification:
  - If a sentiment label exists, classify sentiment from available non-label metadata/text-derived fields where supported.
  - Otherwise, if engagement metrics exist, derive Low/Medium/High engagement categories and predict them using non-engagement metadata to avoid target leakage.
  - If required fields are missing, the app explains why model training is unavailable instead of inventing a result.
- CSV downloads of aggregated outputs.
- A demo report template that must be filled with the values generated by your own run.

## Beginner setup (Windows PowerShell)

1. Install **Python 3.10 or 3.11 (64-bit)** from https://www.python.org/downloads/. During installation, select **Add Python to PATH**.
2. Download this ZIP and extract it to a simple location, for example `C:\BigDataProject`.
3. Open PowerShell in the extracted folder.
4. Create a virtual environment:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   If PowerShell blocks activation, run this once in the current terminal and activate again:

   ```powershell
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   .\.venv\Scripts\Activate.ps1
   ```

5. Install packages:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

6. Download the CSV from the Kaggle dataset page. Copy the CSV into `data` and use the filename `multi_platform_social_sentiment_evolution.csv`.
7. Start the dashboard:

   ```powershell
   streamlit run app.py
   ```

   The browser should open automatically. If not, open the local URL printed in the terminal (usually `http://localhost:8501`).

## First run

The dashboard reads the CSV with PySpark. If the default CSV is not found, upload the dataset in the sidebar. The first Spark start may take several seconds.

Do not rename or remove the source columns before the app inspects them. The app performs case-insensitive matching for common aliases, but no automated alias mapping can guarantee every unknown schema. Review the detected-column panel and the data preview.

## What counts as real results?

The dashboard computes results from the CSV supplied by the user. No performance numbers are hardcoded. Model metrics appear only if training succeeds. For a valid report, record the dataset's actual row count, the displayed model metrics, and screenshots from your run. If the dataset lacks a required field, document that limitation honestly.

## Big Data concepts demonstrated

- **Volume:** dataset size and scalable processing design; a local run is a demonstration, not proof of a multi-node cluster.
- **Variety:** numeric metrics, categorical metadata, dates, text and sentiment labels if present.
- **Veracity:** duplicate/missing-value checks and type handling.
- **Velocity (simulation only):** this version analyzes stored snapshots. It does not claim a live social-media feed.
- **Distributed processing:** PySpark DataFrame transformations and aggregations using `local[*]`.
- **Data mining / ML:** topic rankings, trends, and optional classification.

## Important limitation

This is a local PySpark project. It does not deploy a Hadoop cluster, HDFS, HBase, YARN, ZooKeeper, or live platform API ingestion. Mention these as possible production extensions only, not as implemented features.
